Emberline.

A puzzle-platformer built around one transferable flame.

01 / INTERACTIVE

The idea

Emberline is a 2D puzzle-platformer in which light changes what the player can see and do. The player carries a flame that can be thrown, transferred, or placed in mechanisms around the level. Moving the flame changes the environment: a bridge may become usable, a vine may grow, or a mechanism may become available only when the light has moved elsewhere.

I wanted the player to solve puzzles by experimenting with the same small set of actions and noticing how the level responds. Each new situation builds on a familiar rule, then asks the player to apply it under different spatial conditions.

02 / INTERACTIVE

One flame, multiple holders

I designed the game around a central FlameState system that tracks which object currently holds the flame. A player, thrown flame, or compatible mechanism can serve as its holder. Transfers pass through a single validated operation, try_transfer(), which updates ownership and emits an event when the flame moves. The visual effect follows the current holder, and an illumination check uses the flame's world position to determine which nearby objects receive light.

This arrangement lets different mechanisms react to the same shared state. It also gives the player a consistent rule: relocating the flame changes the opportunities available elsewhere in the scene.

03 / INTERACTIVE

Throwing, returning, and interacting

The thrown flame is a separate Godot object with outward movement, deceleration, and a returning phase. It can transfer into a compatible receiver when it reaches one, or travel back toward the player when its outward motion ends or it encounters an obstruction. The player can also pass the flame directly between nearby holders.

I combined these interactions with platforming controls for moving, jumping, and climbing. The different actions matter together: the player may need to throw the flame to reach a distant receiver, climb to a newly accessible route, or retrieve the flame before moving to the next section.

04 / INTERACTIVE

Designing environmental responses

I implemented several reusable environmental components. Light-dependent platforms and mechanisms respond to illumination or flame ownership. Bridges change state when connected receivers gain or lose power. Photosynthetic vines grow or retract in response to their lighting conditions, changing the routes available to the player. Dark-dependent interactions ask the player to think about where light should be absent as well as where it should be present.

The demo level arranges these systems into a progressive sequence, beginning with basic movement and flame use before combining them in more involved puzzles. Checkpoints, hazards, audiovisual cues, and a victory condition provide feedback and structure for the completed playthrough.

05 / INTERACTIVE

Building and testing the demo

I developed the mechanics, player controls, scene connections, and level independently in Godot. I also created dedicated test scenes for specific behaviors, including flame throwing, jumping, platforms, vines, and onboarding. Working with a reusable set of components made it possible to refine one interaction and then apply it throughout the level.

A playable desktop-browser version is embedded below. I also have macOS and Windows builds of the demo.

PLAY THE DEMO

Play Emberline

Click inside the game to focus it. Use arrow keys to move and climb, Space to jump, hold Q to aim and release to throw the flame, F to pass it, E to interact, and R to restart. A desktop keyboard is recommended.
